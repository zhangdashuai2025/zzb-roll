# 将确认的 B-roll 接入现有工程

此参考只在用户明确要求“应用”“替换”“导出”时读取。先检查目标工程自己的结构、Schema 和保存服务，不假设任何固定盘符或作者目录。

1. 确认草稿与用户批准的预览同版本；备份工程 JSON、保留其依赖的旧组件和素材。禁止仅修改旧组件硬编码文案导致历史项目画面变化。
2. 新场景有独立 ID/命名空间。持久化结构需同时通过前端类型、后端校验和保存/重开；不要让旧 Schema 静默剥离新字段。
3. Player、编辑器、合成与透明层导出引用同一 Remotion 场景。B-roll 的 `enabled`、起止帧、位置、尺寸、内部可编辑字段、`soundEnabled` 与 `soundVolume` 应在保存后保留。独立处理 A-roll 音轨。
4. 编辑画布时拖动位置不应改大小；缩放只在把手模式生效。时间轴移动播放头与移动/裁切片段需区分。未刷新的旧标签页不能覆盖已更新工程。
5. 对照关键帧目检完整列表、结尾 CTA、透明区域；测试刷新、预览→编辑器返回、调整后重开。导出前保存最新状态。

MP4 渲染后检查画面、声音、时长；ProRes 4444 MOV 检查 Alpha，且不混入 A-roll 背景。只测了几帧时不要声称整片已验证。
