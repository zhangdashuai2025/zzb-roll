# zzb-roll：字幕重点 → Remotion 动效

默认中文交流。复用的是分析、设计、审核、预览、交付流程，不是把新字幕机械填进旧模板。仅凭安装 skill 不会自动安装 Remotion 或生成视频；需要用户给视频与 SRT，Codex 在本地工程中实施。

## 输入与边界

- 使用本次给定的视频文件或可读取的视频链接、SRT 和参考画面。可先核对目标工程的 `AGENTS.md`、`package.json`、已有素材与时间线；没有工程时，在用户指定的工作目录建立独立 Remotion 工程。不要写入 skill 安装目录。
- 网络视频无法直接读取时，说明需要本地视频文件或可访问的下载方式。SRT 只有句级时间时不声称词级对齐。用 `node <skill目录>/scripts/inspect-srt.mjs <字幕.srt> --fps 30` 检查时间和来源 ID。
- 新视频先做独立草稿，不覆盖用户现有工程。分析与预览不等于应用，更不等于导出。素材和渲染在本地；Codex 推理可能联网，不宣称完全离线。
- 没有真实截图、图片或数字依据时，不虚构平台界面、评价、统计或素材。视频里已烧录的字幕/卡片是原片像素，不能当独立图层删除。

## 分析与审核

1. 合并相邻字幕成语义段，选有视觉价值的重点，不逐句生成。约 50 秒通常 8–10 组，长片按语义密度调整。
2. 每组给出原文、提炼短语、起止时间、视觉意图。中文短语通常 4–12 字，英文/数字约 18 个可视字符；15 字以上的原字幕不得照搬，必要专名/数字短语除外。保留条件和观点归属。
3. 每条草稿保留 `captionIds`、`sourceText`、`keywords`、`summaryRuleVersion: "keyword-v1"`，保证可追溯。若目标编辑器有 Schema，先读 Schema，再写兼容的建议文件；不要把被丢弃的字段当成已保存。
4. 从重点所在字幕起点开始，通常显示 2–4 秒，避免与下一组明显冲突；分条列表按各条对应字幕依次弹出，前条保留，末条留可读停顿。不够时间就减少条目或拆组。
5. **先把分镜给用户审核。** 用户可修改/取消单条；未经确认不自动写入正式时间线。

设计场景前读 [视觉语言](references/design.md)。不是固定模板：数字、比例、比较、路径、来源、CTA 等根据内容编写新 Remotion 组件。

## 编写与预览

- Remotion 与所有 `@remotion/*` 包使用目标工程的同一版本；新工程可从已验证的 `4.0.517` 起步，不擅自升级旧工程。动画使用帧驱动的 `useCurrentFrame`、`interpolate` 或 `spring`，不用 CSS 动画/计时器控制导出画面。
- 透明图层上摆独立深色半透明卡片，默认白字、蓝 `#53baff` 与黄 `#ffd45c` 重点；按画面人物与字幕安全区调整位置。移动只改变位置，不改变字号和尺寸；横竖屏分别检查。
- Player、合成 MP4、透明 MOV 共用同一套组件和数据。音效与 A-roll 原声分开：每段 B-roll 的弹出音效默认关闭；若用户开启，可独立设置该段音量，音效事件与视觉出现帧同步。关闭时不挂载对应音效，不把原片静音。
- 给用户可播放的预览入口与段落跳转；至少实际播放一段，核对时间推进、字形、遮挡、声音。用户只要预览时，不替换原工程。

## 确认与交付

用户确认预览后才接入正式编辑器或导出。接入现有应用时读 [工程接入](references/integration.md)，备份已有工程并检查保存、重开、时间轴、编辑器往返。若当前界面不能编辑内部文案，不承诺它能编辑。

合成 MP4 应保留 A-roll 画面和原声；透明 MOV 应只含 B-roll，使用 ProRes 4444 与 Alpha，供剪映叠加。透明层不等于单独的透明 MP4。核对导出文件实际存在、时长、音轨和 Alpha 后再报告完成；未运行的验证明确说未验证。
